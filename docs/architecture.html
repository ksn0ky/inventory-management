Factory Inventory Management System

Architecture overview · Vue 3 SPA · FastAPI service · in-memory JSON data (no database)

Overview

A full-stack demo application for factory operations: inventory tracking across warehouses, order management, demand forecasting, backlog monitoring, and spending analytics. The frontend is a single-page Vue 3 app that talks to a stateless FastAPI backend over a small REST API. All domain data is loaded from JSON files into memory at startup — there is no database, and writes do not persist across a server restart.

Data Flow — a filtered dashboard load

  1. User changes a control in FilterBar.vue (Time Period, Warehouse, Category, or Order Status).
  2. The selection updates shared refs in useFilters.js; a watch in the active view fires and calls loadData().
  3. getCurrentFilters() maps UI state to an API params object (warehouse, category, status, and month when a period is set).
  4. api.js serialises those into a query string and issues parallel axios GETs (/dashboard/summary, /orders, /inventory, /backlog).
  5. FastAPI handlers run apply_filters() then filter_by_month() over the in-memory lists — filtering on copies, never mutating source data.
  6. Results are validated against Pydantic models via response_model and returned as JSON.
  7. The view stores raw responses in refs (allOrders, inventoryItems, summary); computed properties derive KPIs, category rollups, top products, and chart geometry.
  8. Template re-renders reactively; SVG/CSS charts and tables reflect the new derived data.

Key Patterns

Frontend

  • Raw server data lives in ref(); everything derived is a computed().
  • Filter state is a module-level singleton in useFilters, shared across every view.
  • One axios module (api.js) owns all HTTP; views never call axios directly.
  • Loading / error / data are explicit template states on every view.
  • v-for keys use stable ids (sku, id, month) — never the array index.
  • Dates are validated before .getMonth() / parsing.

Backend

  • Two shared helpers (apply_filters, filter_by_month) back every list endpoint.
  • Filters skip when the value is missing or 'all'; string matches are case-insensitive.
  • Time filtering accepts a direct month (2025-03) or a quarter (Q1-2025).
  • Every list route declares a response_model for output validation.
  • Source lists are never mutated — handlers filter over copies.
  • CORS is wide open (allow_origins=["*"]) — demo/dev only.
